# كِتابي | Kitabi

منصة جزائرية مجتمعية لبيع الكتب المدرسية والمراجع وتبادلها والتبرع بها. يعتمد المشروع على React وTypeScript وVite في الواجهة، وعلى Supabase للمصادقة وقاعدة البيانات والتخزين والإشعارات.

## المزايا الرئيسية

| المجال | ما توفره المنصة |
| --- | --- |
| البحث والاكتشاف | بحث سريع، تصفية حسب الطور والمادة والولاية والحالة، وترتيب النتائج |
| الإعلانات | بيع، تبادل، وتبرع مع السعر والحالة والصور ومعلومات التسليم |
| المراجعة | كل إعلان جديد يبدأ بحالة «قيد المراجعة» ولا يظهر للعامة إلا بعد اعتماد الإدارة |
| حساب المستخدم | تعديل الملف الشخصي، تعديل الإعلان، الحذف، ووضع الإعلان كمباع أو غير متوفر |
| التفاعل | المفضلة، المحادثات، طلبات التبادل، البلاغات، والتقييمات |
| الإدارة | إحصائيات الإعلانات، مراجعة الناشرين، اعتماد أو رفض الإعلانات، وإدارة البلاغات |
| الخصوصية | التصفح العام متاح، بينما النشر والتواصل وبيانات الاتصال تتطلب حسابًا |

## التقنية

المشروع مبني باستخدام **React 19** و**TypeScript** و**Vite** و**Tailwind CSS 4**، مع `lucide-react` للأيقونات و`motion` للحركات الخفيفة. تعتمد البيانات الحقيقية على **Supabase Auth** و**Postgres** و**Storage** و**Realtime**. لا يعتمد التطبيق على Firebase.

## التشغيل محليًا

يتطلب المشروع Node.js 20 أو أحدث.

```bash
npm install
cp .env.example .env.local
npm run dev
```

ثم افتح [http://localhost:3000](http://localhost:3000).

## متغيرات البيئة

ضع القيم التالية في `.env.local` محليًا، وفي Vercel ضمن بيئات **Production** و**Preview** و**Development**:

```env
VITE_SUPABASE_URL=https://your-project-ref.supabase.co
VITE_SUPABASE_ANON_KEY=your-publishable-or-anon-key
```

استخدم مفتاح Supabase publishable أو anon فقط في الواجهة. لا تضع `service_role` أو أي مفتاح سري في متغير يبدأ بـ`VITE_`، ولا ترفعه إلى GitHub.

## إعداد Supabase

أنشئ الجداول والسياسات الموجودة في مجلد `supabase/` داخل مشروع Supabase الخاص بك. يجب أن تكون المصادقة مفعّلة، وأن ينشئ trigger الخاص بالمستخدم الجديد صفًا في `public.profiles`.

يجب ضبط bucket الصور `book-images` على الأنواع `image/jpeg` و`image/png` و`image/webp`، مع حد أقصى 5 ميغابايت، وأن تسمح سياسة الرفع بأن يكون المجلد الأول مساويًا لـ`auth.uid()`.

اجعل دور المسؤول داخل `public.profiles.role` يساوي `admin` للحساب الذي سيستخدم لوحة التحكم. لا يكفي إخفاء الرابط من الواجهة؛ لوحة التحكم نفسها تتحقق من جلسة Supabase والدور، كما تحمي RLS العمليات الحساسة.

## دورة الإعلان

عند نشر إعلان جديد، يحفظه التطبيق بحالة `pending`. لا يستطيع الزائر رؤيته. يراجع المسؤول الصور والمعلومات والناشر، ثم يغيّر الحالة إلى `active` أو `flagged` مع سبب الرفض. عند تعديل إعلان فعال، يعود تلقائيًا إلى `pending` لمراجعة جديدة.

## النشر على Vercel

المشروع مهيأ كتطبيق Vite أحادي الصفحة:

| الإعداد | القيمة |
| --- | --- |
| Framework Preset | Vite |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Install Command | `npm install` |
| Node.js | 20.x أو أحدث |

يوفر `vercel.json` إعادة توجيه لمسارات التطبيق إلى `index.html` وترويسات حماية، من بينها CSP وHSTS و`X-Frame-Options` و`X-Content-Type-Options`. بعد إضافة متغيرات Supabase، نفّذ نشرًا جديدًا ثم اختبر `/` و`/marketplace` و`/admin` و`/privacy` و`/terms`.

## بنية المشروع

```text
src/
├── components/        # مكونات الواجهة والنوافذ المنبثقة ولوحة الإدارة
├── data/              # بيانات الأطوار والولايات فقط، دون إعلانات تجريبية
├── services/          # Supabase، الإشعارات، التقييمات، وخدمات التطبيق
├── types/             # الأنواع المشتركة في TypeScript
├── App.tsx            # الحالة العامة والمصادقة والتنقل
├── index.css          # الهوية البصرية والأنماط العامة
└── main.tsx           # نقطة دخول React

supabase/
├── schema.sql         # المخطط المرجعي
└── migrations/        # تعديلات الأمان والمراجعة والإشعارات
```

## ملاحظات الخصوصية والأمان

لا تُعرض إعلانات `pending` أو `flagged` للزوار. كما يجب أن تبقى أرقام الهاتف وبيانات الاتصال ضمن المسارات التي تسمح بها RLS للمستخدمين المسجلين فقط. الصور العامة قابلة للعرض عبر روابط Storage، لكن الرفع والحذف محميان بسياسات المجلد والمالك.

تستخدم الواجهة `localStorage` فقط لتفضيلات البحث والكاش المحلي الخفيف. أما الإعلانات والمستخدمون والمفضلة والمحادثات وطلبات التبادل والبلاغات والصور فتعتمد على Supabase.
